# Spring Boot 가이드 — 설명

목록에서 본 주제를 순서대로 설명합니다.  
코드는 [02-예제.md](./02-예제.md)에 모아 두었습니다.

기준: **Java 21**, **Gradle**, **JPA + QueryDSL**(단순 CRUD), **MyBatis**(복잡한 쿼리).

---

## 1. Spring Boot란?

Spring은 Java 웹 애플리케이션을 만들 때 쓰는 프레임워크입니다.  
**Spring Boot**는 서버 설치와 XML 설정을 줄여 바로 실행할 수 있게 합니다.

- **내장 Tomcat**: `./gradlew bootRun`만으로 HTTP 서버가 뜹니다.
- **자동 설정**: `application.yml`과 Starter만 있으면 웹·JPA·MyBatis가 붙습니다.
- **Java 21**: 레코드, 텍스트 블록, 가상 스레드 등을 쓸 수 있습니다.
- **Spring Boot 3**: `javax.*` 대신 **`jakarta.*`** 패키지를 씁니다. QueryDSL도 `jakarta` classifier가 필요합니다.

---

## 2. 프로젝트 구조

요청은 항상 아래로만 흐릅니다.

```
브라우저(React)
    → Controller
        → Service
            → JPA Repository / QueryDSL     (단순 CRUD)
            → MyBatis Mapper                (복잡한 SQL)
```

| 패키지 | 역할 |
|--------|------|
| `controller` | HTTP만 담당. SQL을 쓰지 않는다 |
| `service` | 업무 규칙. JPA와 MyBatis 중 무엇을 호출할지 정한다 |
| `domain` | 테이블과 1:1에 가까운 JPA Entity |
| `repository.jpa` | `JpaRepository` + QueryDSL |
| `repository.mybatis` | `@Mapper` 인터페이스 |
| `dto` | API JSON. Entity를 그대로 노출하지 않는다 |
| `config` | CORS, `JPAQueryFactory` |
| `resources/mapper` | MyBatis XML |

Service가 **두 저장소를 함께** 쓸 수 있습니다.  
예: 팝업 확인은 JPA로 INSERT/DELETE, 그리드 재조회는 MyBatis JOIN.

---

## 3. Gradle과 Starter

Maven의 `pom.xml` 대신 **Gradle**의 `build.gradle` / `settings.gradle`을 씁니다.

| 파일 | 역할 |
|------|------|
| `settings.gradle` | 프로젝트 이름 |
| `build.gradle` | 플러그인, Java 21, 의존성 |
| `gradlew` / `gradlew.bat` | Gradle Wrapper. Gradle을 따로 설치하지 않음 |

Java 버전은 툴체인으로 고정합니다.

```gradle
java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}
```

**Starter**는 기능 묶음입니다.

| 의존성 | 하는 일 |
|--------|---------|
| `spring-boot-starter-web` | REST, Tomcat, Jackson |
| `spring-boot-starter-data-jpa` | Hibernate, `JpaRepository` |
| `querydsl-jpa` (`jakarta`) | 타입 안전한 쿼리, Q클래스 |
| `mybatis-spring-boot-starter` | `@Mapper`, XML SQL |
| `ojdbc11` | Oracle (Java 21용. ojdbc8 아님) |

QueryDSL은 Entity를 컴파일할 때 **Q클래스**(`QAuthExcel` 등)를 생성합니다.  
`annotationProcessor`에 `querydsl-apt:jakarta`와 `jakarta.persistence-api`가 있어야 Q클래스가 나옵니다.

## 4. 애플리케이션 진입점

`main` + `@SpringBootApplication`이 시작점입니다.

컴포넌트 스캔 범위는 이 클래스가 있는 패키지와 하위입니다.  
MyBatis 매퍼는 JPA처럼 자동 스캔되지 않으므로 **`@MapperScan`**으로 인터페이스 패키지를 지정합니다.

```
@SpringBootApplication
@MapperScan("com.company.reactbeginner.repository.mybatis")
```

패키지를 스캔 범위 밖에 두면 Controller도 API도 등록되지 않습니다.

## 5. 설정과 프로파일

Boot 3에서는 `application.yml`을 많이 씁니다. `.properties`도 가능합니다.

자주 쓰는 키:

| 키 | 의미 |
|----|------|
| `server.port` | HTTP 포트 (8080) |
| `spring.datasource.*` | JDBC URL, 계정 |
| `spring.jpa.hibernate.ddl-auto` | Entity로 테이블을 만들지 여부. 운영은 `none` |
| `spring.jpa.open-in-view` | 권장: `false` (트랜잭션 밖에서 지연로딩 금지) |
| `mybatis.mapper-locations` | XML 위치 (`classpath:mapper/**/*.xml`) |
| `mybatis.configuration.map-underscore-to-camel-case` | `DETAIL_ID` → `detailId` |

**프로파일**: `application.yml`(공통) + `application-local.yml`(로컬 계정).  
계정·비밀번호는 git에 올리지 않습니다.

Oracle URL 예: `jdbc:oracle:thin:@localhost:1521/FREEPDB1`

## 6. 의존성 주입 (DI)

생성자가 하나면 Spring이 자동 주입합니다.

```
B002Controller(B002AuthService)
B002AuthService(AuthExcelDetailRepository, B002AuthMapper)
```

Service 생성자에 **JPA 리포지토리와 MyBatis 매퍼를 같이** 넣을 수 있습니다.  
둘 다 Spring 빈입니다.

## 7. REST Controller

`@RestController` = 반환값이 JSON 본문입니다.

| 애노테이션 | 역할 |
|------------|------|
| `@RequestMapping("/api/b002")` | 클래스 URL prefix |
| `@GetMapping` | 조회 |
| `@PostMapping` | 등록·동기화 |
| `@PutMapping` | 수정 |
| `@DeleteMapping` | 삭제 |

Controller는 파라미터를 받아 Service만 호출하고 `{ success, data }`로 감쌉니다.  
`entityManager`, `JPAQueryFactory`, SQL 문자열은 Controller에 두지 않습니다.

---

## 8. 요청 파라미터

- **GET 쿼리**: `@RequestParam`. 기본은 필수, `required = false`면 생략 가능.
- **JSON 바디**: `@RequestBody` + DTO. Jackson이 키와 getter/setter(또는 레코드 컴포넌트)를 맞춥니다.

Java 21에서는 요청/응답 DTO를 **`record`**로 쓸 수 있습니다.

```java
public record CodeNameDto(String code, String name) {}
```

불변이고 getter 보일러플레이트가 없습니다. JSON 키는 `code`, `name`입니다.

---

## 9. 응답 JSON

```json
{
  "success": true,
  "data": [ ... ],
  "totalCount": 10
}
```

Entity를 그대로 반환하지 않는 이유:

- 양방향 연관이 있으면 JSON이 순환합니다
- 컬럼과 화면 필드가 다를 수 있습니다
- 비밀번호·내부 PK를 숨기기 쉽습니다

조회 결과가 복잡하면 MyBatis가 바로 조회 DTO로 매핑하는 편이 낫습니다.

---

## 10. Service

Service가 저장소 종류를 고릅니다.

| 메서드 성격 | 호출 대상 |
|-------------|-----------|
| 상세 1건, 옵션 전표, 한 행 저장/삭제 | JPA / QueryDSL |
| 그리드 JOIN 목록, 리포트성 SQL | MyBatis |
| 팝업 확인: 여러 INSERT/DELETE | JPA + `@Transactional` |

SQL 문자열과 QueryDSL `BooleanExpression`은 Service에 길게 두지 않습니다.  
조건 조립은 QueryDSL 전용 리포지토리 또는 MyBatis XML로 내립니다.

---

## 11. Entity와 DTO

**Entity** (`@Entity`): 테이블 행. JPA가 관리하는 영속 객체입니다.

- `@Id`, `@GeneratedValue` 또는 시퀀스
- `@Column(name = "EMP_NO")` — DB는 대문자 스네이크, 필드는 카멜
- 단순 CRUD의 출발점. QueryDSL Q클래스는 Entity에서 생성됩니다

**DTO**: API와 화면용. JOIN 결과처럼 테이블과 모양이 다르면 Entity가 아니라 DTO입니다.

한 Entity를 그리드 JOIN 결과에 억지로 맞추지 마세요. 그때는 MyBatis + DTO입니다.

---

## 12. JPA 기본 CRUD

`JpaRepository<엔티티, PK타입>`를 상속하면 메서드가 생깁니다.

| 메서드 | SQL에 해당 |
|--------|------------|
| `findById(id)` | SELECT … WHERE PK |
| `findAll()` | SELECT 전체 |
| `save(entity)` | INSERT 또는 UPDATE |
| `deleteById(id)` | DELETE |
| `existsById(id)` | 존재 여부 |

메서드 이름으로 단순 조건도 됩니다. 예: `findByDeptName(String deptName)`.

한계:

- JOIN이 많아지면 메서드 이름·JPQL이 읽기 어렵습니다
- 동적 조건(값 있을 때만 WHERE)은 QueryDSL이나 MyBatis가 낫습니다

그래서 **한 테이블 + 조건 몇 개**까지만 JPA/QueryDSL로 두고, 그 이상은 MyBatis로 넘깁니다.

---

## 13. QueryDSL

QueryDSL은 **문자열 JPQL 대신 Q클래스 필드**로 쿼리를 짭니다.  
오타가 컴파일 시점에 납니다.

쓰는 흐름:

1. Entity 컴파일 → `QAuthExcel`, `QAuthExcelDetail` 생성
2. `QuerydslConfig`에서 `JPAQueryFactory` 빈 등록
3. `AuthExcelQueryRepository`에서 `queryFactory.selectFrom(q).where(...)`

적합한 것:

- `useYn.eq("Y")`
- 부서 코드가 있을 때만 `deptName.eq(dept)`
- 정렬, 페이징(`offset` / `limit`)
- 한두 테이블의 조건 검색

적합하지 않은 것:

- Oracle 힌트, `NVL`, 계층 쿼리, 긴 UNION
- 화면 그리드용 넓은 JOIN + 별칭 많은 SELECT 목록

그때는 MyBatis XML이 명확합니다.

Boot 3 / Jakarta에서는 의존성에 **`:jakarta` classifier**를 빼먹으면 Q클래스가 안 생기거나 `javax.persistence`를 찾습니다.

---

## 14. MyBatis

MyBatis는 SQL을 XML(또는 애노테이션)에 그대로 적습니다.  
복잡한 조회는 DBA·기존 회사 SQL을 거의 복사해 넣을 수 있습니다.

구성:

| 파일 | 역할 |
|------|------|
| `B002AuthMapper.java` | `@Mapper` 메서드 시그니처 |
| `B002AuthMapper.xml` | 같은 `namespace`의 SQL |
| `application.yml` | `mapper-locations` |

동적 SQL:

- `<if test="deptName != null">` — 조건이 있을 때만 WHERE 추가
- `<foreach>` — IN 절
- `<choose>` — 분기

결과 매핑:

- `resultType`에 DTO 풀 네임
- `map-underscore-to-camel-case: true`이면 `EMP_NO` → `empNo`

INSERT/UPDATE/DELETE도 MyBatis로 할 수 있지만,  
이 가이드의 규칙은 **단순 변경은 JPA**, **복잡한 SELECT는 MyBatis**입니다.

같은 트랜잭션에서 JPA `save`와 MyBatis `insert`를 섞을 수는 있습니다.  
다만 같은 테이블을 양쪽에서 동시에 만지면 영속성 컨텍스트와 DB가 어긋날 수 있습니다.  
한 업무 단위에서는 **쓰기는 한쪽으로** 모으는 것이 안전합니다.

## 15. 언제 JPA / 언제 MyBatis

| 질문 | 예 | 선택 |
|------|----|------|
| 테이블 하나, PK로 찾나? | 상세 팝업 로드 | JPA `findById` |
| 조건 2~3개, 동적 여부만? | 사용여부 + 부서 | QueryDSL |
| 한 행 넣고 지우나? | 세부권한 체크 동기화 | JPA `save` / `delete` |
| 두 테이블을 붙여 그리드 컬럼을 만드나? | t1 JOIN t2 | MyBatis |
| Oracle 전용 함수·힌트가 있나? | `NVL`, `TO_CHAR` | MyBatis |
| SELECT 컬럼이 화면 DTO와 거의 같나? | 플랫 그리드 | MyBatis `resultType` |
| 연관 Entity를 그래프로 다루나? | 부모-자식 영속 | JPA |

애매하면 **조회는 MyBatis, 변경은 JPA**로 시작하면 실수가 적습니다.

---

## 16. 트랜잭션

`@Transactional`은 **Service 메서드**에 붙입니다.

- 정상 종료 → 커밋
- 런타임 예외 → 롤백

B002 팝업 확인은 DELETE 여러 건 + INSERT 여러 건입니다.  
중간에 실패하면 일부만 지워지면 안 되므로 한 메서드에 `@Transactional`을 둡니다.

JPA와 MyBatis가 **같은 DataSource**를 쓰면 같은 트랜잭션에 참여합니다.  
읽기 전용 그리드 조회는 `@Transactional(readOnly = true)`를 쓸 수 있습니다.

## 18. 실행과 요청 흐름

### 실행

```bash
cd backend
./gradlew bootRun          # Linux / macOS
gradlew.bat bootRun        # Windows
```

필요 조건: **JDK 21**, Wrapper 사용 시 Gradle 설치 불필요.  
B002는 Oracle + 로컬 계정. 콘솔에 `Tomcat started on port(s): 8080`이면 성공입니다.

### B002 그리드 조회 (복잡 → MyBatis)

1. 조회 버튼
2. `GET /api/b002/search?departmentCode=개발부`
3. `B002Controller` → `B002AuthService.search`
4. `B002AuthMapper.findAuthExcelRows` + XML JOIN
5. `{ success, data, totalCount }`

### B002 세부권한 저장 (단순 → JPA)

1. 팝업 확인
2. `POST /api/b002/details/sync`
3. Service `@Transactional`
4. 빠진 행 `delete`, 새 행 `save`
5. 필요하면 이후 목록만 MyBatis로 다시 조회

문제가 나면 Network → Controller → Service → (QueryDSL / mapper XML) 순으로 내려가 보면 됩니다.
