# Spring Boot 가이드 — 설명

목록에서 본 15개 주제를 순서대로 설명합니다.  
코드는 [02-예제.md](./02-예제.md)에 모아 두었습니다.

---

## 1. Spring Boot란?

Spring은 Java 웹 애플리케이션을 만들 때 쓰는 프레임워크입니다.  
다만 예전 Spring은 XML 설정, 서버(Tomcat) 설치, 의존성 조합이 번거로웠습니다.

**Spring Boot**는 그 과정을 줄여 줍니다.

- **내장 서버**: Tomcat이 앱 안에 들어 있어서 `java` / Maven만으로 실행됩니다.
- **자동 설정**: `application.properties`와 Starter만 있으면 웹·DB가 붙습니다.
- **실행 가능한 JAR**: 하나의 파일로 배포할 수 있습니다.

이 프로젝트는 **Spring Boot 2.7.18 + Java 8**입니다.  
회사 레거시와 맞춰 둔 버전이므로, 학습할 때도 이 조합을 기준으로 보세요.

## 2. 프로젝트 구조

백엔드는 Maven 표준 디렉터리를 따릅니다.

| 경로 | 역할 |
|------|------|
| `src/main/java` | 애플리케이션 코드 |
| `src/main/resources` | 설정 파일, SQL이 아닌 리소스 |
| `src/test/java` | 테스트 코드 (현재는 starter-test만 의존) |
| `pom.xml` | 의존성과 빌드 설정 |

패키지는 **역할 단위**로 나눕니다.

| 패키지 | 역할 | 다른 계층을 직접 알면 안 되는가 |
|--------|------|----------------------------------|
| `controller` | HTTP 요청을 받아 응답한다 | Service만 호출한다. SQL을 쓰지 않는다 |
| `service` | 업무 규칙을 처리한다 | Repository 또는 목 데이터를 쓴다 |
| `repository` | DB SQL을 실행한다 | HTTP를 모른다 |
| `dto` | JSON으로 오가는 데이터 | 로직을 거의 두지 않는다 |
| `config` | CORS 같은 공통 설정 | 업무 API와 분리한다 |

요청은 항상 아래로만 흐릅니다.

```
브라우저(React)
    → Controller
        → Service
            → Repository (DB)  또는  목 리스트
```

B001 그리드는 DB 없이 Service가 리스트를 만들고,  
B002 권한은 Service가 Repository의 SQL을 호출합니다.

## 3. Maven과 Starter

Maven은 Java 라이브러리를 받아 빌드하는 도구입니다.  
이 프로젝트는 Maven을 따로 설치하지 않고 **Maven Wrapper** (`mvnw.cmd`)를 씁니다.

`pom.xml`의 `<parent>`가 Spring Boot BOM(버전 묶음)입니다.  
자식 의존성에서 버전을 생략해도 parent가 맞춰 줍니다.

**Starter**는 “이 기능에 필요한 라이브러리 묶음”입니다.

| Starter | 이 프로젝트에서 하는 일 |
|---------|--------------------------|
| `spring-boot-starter-web` | REST API, 내장 Tomcat, Jackson(JSON) |
| `spring-boot-starter-jdbc` | `JdbcTemplate`, 커넥션 풀(HikariCP) |
| `spring-boot-starter-test` | 테스트 라이브러리 |

Oracle 드라이버 `ojdbc8`은 Starter가 아니라 DB 전용 의존성입니다.  
`runtime` 스코프라서 컴파일 코드에서는 직접 import 하지 않고, 실행 시 JDBC URL로 연결됩니다.

## 4. 애플리케이션 진입점

`ReactBeginnerApplication`의 `main`이 시작점입니다.

`@SpringBootApplication`은 세 가지를 한 번에 켭니다.

1. **자동 설정** — classpath의 web, jdbc를 보고 빈을 만듭니다.
2. **컴포넌트 스캔** — 이 클래스가 있는 패키지(`com.company.reactbeginner`)와 하위 패키지에서 `@RestController`, `@Service`, `@Repository`, `@Configuration`을 찾아 빈으로 등록합니다.
3. **설정 클래스** — 이 클래스 자체가 설정 진입점입니다.

그래서 Controller를 `com.company.reactbeginner.controller`에 두면 자동으로 등록됩니다.  
패키지를 그 바깥에 두면 **스캔되지 않아** API가 안 뜹니다.

## 5. 설정과 프로파일

설정은 `src/main/resources/application.properties`에 둡니다.

자주 쓰는 키:

| 키 | 의미 |
|----|------|
| `server.port` | HTTP 포트. 기본 8080 |
| `spring.application.name` | 앱 이름 |
| `spring.profiles.active` | 활성 프로파일 |
| `spring.datasource.url` | JDBC URL |
| `spring.datasource.driver-class-name` | JDBC 드라이버 |
| `spring.datasource.hikari.*` | 커넥션 풀 |

**프로파일**은 환경별 설정을 나누는 이름입니다.

- `application.properties` — 공통
- `application-local.properties` — 로컬 계정 (git 제외)
- `spring.profiles.active=local` 이면 `local` 파일이 덮어씁니다

계정·비밀번호를 공통 파일에 넣지 않는 이유:

- git에 올라가면 유출됩니다
- 사람마다 Oracle 계정이 다릅니다

`application-local.properties.example`을 복사해 본인 계정만 채우면 됩니다.

## 6. 의존성 주입 (DI)

Spring은 객체를 직접 `new` 하기보다 **빈을 컨테이너가 만들고 넣어 줍니다.**

이 프로젝트는 **생성자 주입**을 씁니다.

```
GridController(GridMockService)
B002Controller(B002AuthService)
B002AuthService(B002AuthRepository)
B002AuthRepository(JdbcTemplate)
```

장점:

- 테스트할 때 가짜 객체를 넣기 쉽습니다
- 필수 의존성이 생성자에 드러납니다
- 필드에 `@Autowired`를 덜 써도 됩니다 (생성자가 하나면 Spring이 자동 주입)

`JdbcTemplate`은 `spring-boot-starter-jdbc` + datasource 설정이 있으면 Spring Boot가 빈으로 만들어 줍니다.

## 7. REST Controller

`@RestController` = `@Controller` + `@ResponseBody`  
메서드 반환값이 **뷰 이름**이 아니라 **JSON 본문**이 됩니다.

핵심 애노테이션:

| 애노테이션 | 역할 |
|------------|------|
| `@RestController` | REST 컨트롤러로 등록 |
| `@RequestMapping("/api/grid")` | 클래스 공통 URL prefix |
| `@GetMapping` | HTTP GET |
| `@PostMapping` | HTTP POST |

클래스 prefix + 메서드 경로가 최종 URL입니다.

- `@RequestMapping("/api/grid")` + `@GetMapping("/search")`  
  → `GET /api/grid/search`

Controller의 책임은 짧게 유지합니다.

1. 쿼리/바디를 받는다
2. Service를 호출한다
3. `{ success, data, totalCount }` 형태로 감싼다

필터링·SQL·트랜잭션은 Service / Repository에 둡니다.

---

## 8. 요청 파라미터

### 쿼리스트링 — `@RequestParam`

GET에서 `?week=202627&departmentCode=D01` 처럼 붙는 값입니다.

- 기본은 **필수**입니다. 없으면 400 오류가 납니다.
- `required = false`면 없어도 됩니다. 값은 `null`입니다.

B001 검색은 `week`만 필수이고, 나머지 필터는 선택입니다.

### JSON 바디 — `@RequestBody`

POST에서 JSON을 DTO로 받습니다.

```json
{ "empNo": "1001", "authName": "조회", "selectedDetails": [] }
```

Jackson이 JSON 키와 DTO의 getter/setter 이름을 맞춰 채웁니다.  
필드가 없고 getter/setter만 있어도 됩니다. (JavaBean 규칙)

GET은 조회, POST는 변경(동기화)에 쓰는 것이 이 프로젝트의 패턴입니다.

---

## 9. 응답 JSON

반환 타입이 `Map<String, Object>` 또는 DTO이면 Jackson이 JSON으로 바꿉니다.

공통 응답 형태:

```json
{
  "success": true,
  "data": [ ... ],
  "totalCount": 10
}
```

- `success` — 프론트가 성공 여부를 볼 때 사용
- `data` — 실제 목록 또는 객체
- `totalCount` — 그리드 건수 (검색 API)

`List<CodeNameDto>`를 그대로 반환해도 JSON 배열이 됩니다.  
다만 프론트가 `{ success, data }`를 기대하므로 Controller에서 Map으로 감쌉니다.

DTO 필드명(`code`, `name`)이 JSON 키가 됩니다.  
프론트 `B001Api.js`와 이름을 맞추는 것이 중요합니다.

## 10. Service

Service는 **화면이 모르는 업무 규칙**을 둡니다.

| 서비스 | 데이터 출처 | 하는 일 |
|--------|-------------|---------|
| `GridMockService` | 메모리 리스트 | 주차·부서·팀에 따라 옵션/행을 필터 |
| `B002AuthService` | Oracle | 조회, 옵션, 세부권한 동기화 |

`@Service`가 있어야 컴포넌트 스캔 대상이 됩니다.

B002의 `syncRowDetails`처럼 여러 INSERT/DELETE가 있으면  
“무엇을 지우고 무엇을 넣을지” 결정하는 코드는 Service에 두고,  
SQL 한 줄은 Repository에 둡니다.

---

## 11. DTO

DTO(Data Transfer Object)는 계층 사이로 데이터를 옮기는 객체입니다.

이 프로젝트에서 쓰는 구분:

| 종류 | 예 | 용도 |
|------|----|------|
| 코드-이름 | `CodeNameDto` | 셀렉트/라디오 옵션 |
| 그리드 행 | `GridRowDto`, `B002AuthExcelDto` | 목록 한 줄 |
| 요청 바디 | `B002DetailSyncRequest` | POST JSON |
| 상세 항목 | `B002DetailItemDto`, `DetailListItemDto` | 팝업·동기화 결과 |

Entity(테이블 1:1)를 쓰지 않고 DTO만 쓰는 이유:

- 학습용이라 JPA 없이 JDBC로 컬럼을 DTO에 직접 매핑합니다
- API 응답 모양을 테이블 구조와 다르게 가져가기 쉽습니다

JSON 변환을 위해 **기본 생성자 + getter/setter**가 필요합니다.

---

## 12. Repository와 JdbcTemplate

`@Repository`는 DB 접근 계층입니다.  
이 프로젝트는 JPA가 아니라 **JdbcTemplate**을 씁니다.

`JdbcTemplate`이 대신 해 주는 일:

- 커넥션 얻기 / 반납
- `PreparedStatement`로 `?` 바인딩 (SQL 인젝션 방지)
- `ResultSet`을 `RowMapper`로 DTO 리스트 변환

| 메서드 | 용도 |
|--------|------|
| `query(sql, args, rowMapper)` | SELECT → 리스트 |
| `queryForObject(sql, args, type)` | SELECT 한 값 |
| `update(sql, args)` | INSERT / UPDATE / DELETE |

SQL의 `?` 개수와 인자 배열 길이는 같아야 합니다.  
조건이 있을 때만 `WHERE`를 붙이려면 `StringBuilder` + `List<Object> params` 패턴을 씁니다. (부서 필터)

## 13. 트랜잭션

트랜잭션은 **여러 SQL을 모두 성공하거나 모두 취소**하는 단위입니다.

B002 팝업 확인은 기존 세부권한을 지우고, 새로 고른 항목을 넣습니다.  
중간에 실패하면 일부만 지워진 상태가 되면 안 됩니다.

`@Transactional`을 Service 메서드에 붙이면:

- 메서드가 정상 끝나면 **커밋**
- 런타임 예외가 나면 **롤백**

Controller가 아니라 Service에 붙입니다.  
한 HTTP 요청 안의 업무 단위가 Service이기 때문입니다.

읽기 전용 조회(`search`, `findDistinctDepartments`)에는 굳이 쓰지 않아도 동작합니다.

## 14. CORS

브라우저는 **다른 출처**의 API를 기본 차단합니다.

- 프론트: `http://localhost:5173`
- 백엔드: `http://localhost:8080`

포트가 다르면 다른 출처입니다.  
그래서 `WebConfig`에서 `/api/**`에 대해 5173 origin을 허용합니다.

허용하지 않으면 브라우저 콘솔에 CORS 오류가 나고,  
Network 탭에는 보통 `OPTIONS` preflight만 보이거나 요청이 실패합니다.

운영에서는 허용 origin을 실제 프론트 도메인으로 바꿉니다.  
`*`로 모두 여는 것은 학습용에서도 습관으로 두지 않는 편이 낫습니다.

## 15. 실행과 요청 흐름

### 실행 조건

- **JDK 8** (`javac -version`이 나와야 함. JRE만으로는 컴파일이 안 됨)
- Maven 설치 불필요 — `backend/mvnw.cmd` 사용
- B002 DB 기능을 쓰려면 Oracle과 `application-local.properties` 계정 필요
- B001 목 데이터 API는 DB 없이 동작

### 한 요청의 흐름 (B001 조회)

1. 브라우저에서 조회 버튼 클릭
2. React가 `GET http://localhost:8080/api/grid/search?week=202627&...`
3. CORS 검사 (`WebConfig`)
4. `GridController.search`가 쿼리 파라미터를 받음
5. CSV 문자열을 `List<String>`으로 나눔
6. `GridMockService.searchGrid`가 목 행을 필터
7. `{ success, data, totalCount }` JSON 반환
8. AG Grid가 `data`를 그림

### 한 요청의 흐름 (B002 동기화)

1. 팝업 확인
2. `POST /api/b002/details/sync` + JSON body
3. `B002Controller` → `B002AuthService.syncRowDetails` (`@Transactional`)
4. 현재 DB 목록과 선택 목록을 비교
5. 빠진 항목 DELETE, 새 항목 INSERT (`B002AuthRepository`)
6. 최종 연결 목록을 JSON으로 반환

문제가 생겼을 때는 프론트 Network → Controller → Service → SQL 순으로 내려가며 보면 됩니다.
